	1. Theme
Memory Meets Motion is about building AI systems that don’t just react  they remember and act.
Most AI demos today are stateless: every prompt starts from zero. The next generation of agentic products needs two things working together:
* Memory: Durable, structured, queryable context that persists across sessions, users, and time (facts, relationships, history, preferences).
* Motion: The ability to actually do something with that memory: orchestrate tools, take real-time action, coordinate multiple agents, and respond to live data as it happens.
Teams at this hackathon will build a product, agent, or workflow that demonstrates both halves of this idea working as one system  an AI that knows things and does things because of what it knows.
2. Mandated Tech Stack
Every submitted project must integrate all four of the following sponsor technologies in a meaningful way (not just an API key sitting unused  judges will specifically check for real usage of each). Below is what each one is for and how to slot it into your architecture.
🧠 FalkorDB  The Memory Layer
FalkorDB is a low-latency graph database purpose-built for AI memory and GraphRAG use cases (Cypher-based, built for fast multi-hop queries over knowledge graphs). Use it as the place where your agent’s “memory” actually lives.
How to use it:
* Model your domain as a graph  entities + relationships (e.g., User to Preference, Ticket to Resolution, Player to Move to Outcome).
* Use it as the retrieval backend for RAG instead of (or alongside) a vector store  multi-hop graph traversal gives you relationship-aware context a flat vector search misses.
* Write to it continuously as your agent operates, so memory compounds over the session instead of resetting.

🚀 RocketRide.ai  The Motion / Orchestration Layer
RocketRide is the AI orchestration and agent-execution layer  it’s how your system turns “what the agent knows” into “what the agent does”: tool calls, multi-step task execution, API actions.
How to use it:
* Wire RocketRide as the execution engine that reads from FalkorDB memory and decides/executes the next action.
* Use it to orchestrate calls to external tools/APIs (the actual “motion”  sending an email, booking something, updating a record, hitting a live data source).
* If your project has multiple steps or tool calls chained together, this is the layer that sequences them.
🧑‍🤝‍🧑 Guild.ai  The Multi-Agent / Collaboration Layer
Guild.ai is where multiple agents (or agents + humans) coordinate on a task rather than one monolithic agent trying to do everything.
How to use it:
* Split your problem into specialist agents (e.g., a “researcher” agent, a “planner” agent, a “critic” agent) and use Guild.ai to coordinate handoffs between them.
* Use it for human-in-the-loop moments  where your system should pause and route a decision to a person before acting.
* Good fit anywhere your project benefits from division of labor instead of one giant prompt.
📡 LaserData  The Real-Time Data Layer
LaserData is your live/streaming data source  the signal that gives your agent something current to react to, rather than only static/historical memory.
How to use it:
* Feed live or fast-changing data into your system (market data, sensor/motion feeds, event streams, activity logs  whatever fits your idea) so the agent has something happening right now to respond to.
* Pair it directly with FalkorDB: LaserData is the live input, FalkorDB is where that input gets persisted into long-term structured memory.
Note on Judging: Judging will specifically look for load-bearing use of all four technologies. A one-line SDK import that’s never called again will not count.
